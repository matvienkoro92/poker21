# Подписки на активные столы

В обоих ботах кнопка «🔔 Подписаться» открывает два сценария:

- Игра: Холдем, PLO4/5/6, Дурак, 21, OFC, Сека. Лимит — любой,
  точный `5/10` или «от `25/50`» (сравнивается большой блайнд).
- Игрок: поиск по нику из последнего отчёта или ввод Poker21 ID.
  Выбранный ID сохраняется независимо от ника.

Подписки относятся к публичному союзу Анти-Рег (`leagueId: 184691`).
В группе кнопка даёт ссылку на личку текущего бота; пользователь нажимает
Start и включает подписку самостоятельно. `/подписки`, `/subscriptions`
и `/start tablesub` открывают личное меню. «Мои подписки» позволяет удалить
каждую подписку. Максимум 20 подписок на пользователя в каждом боте.

При включении записывается текущая рассадка. Сообщения отправляются при
переходе стола в активное состояние или появлении игрока за новым столом.
Повторная посадка после наблюдаемого ухода также вызывает уведомление.
При неизменной рассадке подписки не перезаписываются в Redis; порядок строк
в ответе API не считается изменением.
При ошибке API предыдущая рассадка сохраняется. Уведомления используют
проверку прав пользователя, блокировку и маркеры доставки, чтобы параллельные
запуски не дублировали сообщения. Заблокировавшие бота пользователи исключаются.

Общий процесс работает в проекте клубного мини-приложения и запускается
Vercel каждые 5 минут через `/api/cron-table-subscriptions`. Он получает
рассадку один раз и сравнивает её отпечаток с предыдущим. При неизменной
рассадке и отсутствии незавершённой работы не читает подписки пользователей
и не вызывает второй проект. Перестановка строк API, смена названия стола и
пересадка внутри того же стола не считаются новыми событиями.

При изменениях клубный бот обрабатывает полученный снимок локально, а бот
Poker21 получает тот же снимок защищённым POST-запросом. Каждый использует
свою базу Redis и отправляет уведомления своим токеном Telegram. Отдельный
cron Poker21 для подписок удалён. Неудачные отправки и незавершённые очереди
повторяются при следующем запуске даже без изменения отпечатка.

Для Production требуются Redis, токен каждого бота и `CRON_SECRET` в каждом
проекте. В клубном проекте необходимо установить
`TABLE_SUBSCRIPTIONS_REPORT_SECRET` равным существующему `CRON_SECRET` проекта
Poker21. Секрет передаётся в заголовке `x-cron-secret`, не в URL и не в коде.
Без этой настройки общий процесс возвращает ошибку, чтобы уведомления
второго бота не отключались молча. Развёртывание: сначала обновить Poker21
(приём снимков), затем клубный проект (общий cron).

Endpoint Poker21 принимает только аутентифицированный POST с массивом
`tables`; не запускает собственный запрос к Poker21 API. В каждом боте за
запуск отправляется до 30 сообщений; незавершённая очередь сохраняется.
Маркеры доставки хранятся 24 часа, чтобы повторы через 5 минут не дублировали
уже отправленные сообщения незавершённого пакета. При наблюдаемом уходе
со стола маркер удаляется, и новая посадка вновь вызывает уведомление.

Изменения, полностью произошедшие между проверками, API не позволяет увидеть.
Текущий API не возвращает рассадку всех турнирных столов; уведомления о посадке
для таких столов возможны только после появления `pos` в ответе поставщика.

Проверка: `node --test tests/table-subscriptions.test.js`.
